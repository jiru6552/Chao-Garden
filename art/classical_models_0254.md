# Ionic school pillars and Hero cornice

The ten authored Kindergarten pillars now use a molded base at Y80, three slim fluted shaft blocks at Y81–83, and an Ionic capital at Y84. The reduced 14-pixel abacus contacts the existing Y85 ceiling at its central face. Its lower support plate begins at 13.4 model pixels, above the 13.3-pixel scroll crown, so it does not mask the upper arc. The two existing column BlockItems remain the complete registry domain; their finite `part` state selects `base`, `shaft`, or `capital` and all four horizontal facings work. The exterior keeps the school's blue stone palette and the interior uses cream stone.

The capital has paired three dimensional stepped circular volutes, spiral relief on both viewing faces, a continuous central echinus, and a square abacus. Twelve raised shaft fillets leave actual recessed flutes rather than a square shaft with painted stripes. The entire fluted profile is inset by half a model pixel on each side (envelope 4–12), within the base neck (3.75–12.25), keeping the ribs aligned with the molding below. Native picking and collision use the authored member envelope, including projecting scrolls. The architectural study is the Ionic order diagram in the [Metropolitan Museum of Art's Greek Art educator publication](https://resources.metmuseum.org/resources/metpublications/pdf/Greek_Art_From_Prehistoric_to_Classical.pdf). The geometry and all new texture pixels are authored here.

The existing `hero_marble_trim` BlockItem now has exactly eight native blockstates: four outer facings and straight/corner. Both the pavilion and fountain cornice rings place straight members along their respective runs and four corner members each. A quarter annulus turns all six soffit molding stripes continuously through each corner, while complete rosettes remain within individual blocks. Interior roof cells use marble rather than unoriented cornice artwork.

Native 1.21.1 `FaceInfo.DOWN`, `BlockFaceUV`, and `FaceBakery.fillVertex` were checked against the cached mapped Minecraft source. A DOWN face with default `[0,0,16,16]` UV maps U toward +X and V toward -Z. The cornice explicitly uses `[0,16,16,0]` so its canonical northwest corner joins the east and south runs. The four blockstate Y rotations then preserve this relationship around the entire ring; `uvlock` is deliberately absent.

`scripts/generate_classical_models_0254.py` is a deterministic postpass after the original school and Hero generators. It also emits the Java picking/collision mesh table. `art/validate_classical_models_0254.py --self-test` examines the actual member elements, slim shaft, physical flutes, both scroll faces, reduced ceiling-contact abacus, texel aspect, finite state/model domains, and corner/straight texture edge pixels. Mutations remove flutes or scrolls, reverse a corner, and stretch the soffit UV; each must fail. The ordinary environment and Hero validators preserve their registry guards and accept only these explicit finite state extensions.

`ClassicalModelsGameTests0254` checks all nine built school stacks and their solid ceiling contacts, compares packaged JSON element unions with actual native picking and collision for both IDs, all three parts and four facings, and checks all 58 placed cornice cells and exactly eight real corner states across the two Hero structures. These checks concern native geometry, resources and placement; they do not substitute a diagram for an actual game capture.

## Native initialization performance correction

The first native server initialization exposed a real hot stack in `IonicColumnMesh0254.<clinit>`: `Shapes.or` called `VoxelShape.optimize` after every appended capital box, repeatedly rebuilding the fine scroll coordinate grid during registry freeze. The capital contains 231 authored boxes. The corrected initializer unions members in a balanced tree using native `Shapes.joinUnoptimized` and optimizes the complete result once. Geometry, textures, blockstates, registration IDs, picking footprints and collision footprints are unchanged.

A separate temporary Java microbenchmark used the actual cached mapped Minecraft classes and the complete capital data. In one comparison, balanced unions without final optimization took 1,197 ms and retained a 228 × 115 × 26 coordinate grid. One final optimization took 1,619 ms and reduced this to 204 × 97 × 22 coordinates, retaining exactly 442 decomposed boxes. Decomposing the resulting shape took 21.3 ms versus 6.75 ms; 100 identical synthetic native raycasts took 582 ms versus 312 ms. This supported retaining one final optimization for native query efficiency. The original repeated optimization did not finish a single-capital benchmark within its 15 second bound. These are isolated Java construction/query measurements, not client frame rate measurements.

The GameTest resource oracle uses a different construction: it reads the packaged JSON model elements and directly fills one exact `BitSetDiscreteVoxelShape` coordinate grid. It compares that independently built union against the production native picking and collision shapes across every member/facing. This also prevents the verification itself from reintroducing the original repeated-optimization cost. Determinism checks confirmed all affected native model, state and texture bytes were unchanged by the performance correction, and that the emitted Java mesh source is reproducible.
