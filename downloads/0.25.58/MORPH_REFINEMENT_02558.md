# Neutral and Hero morphology refinement — 0.25.58

This focused update refines the existing **Neutral / Normal-first-type** and **Hero / Normal-first-type** adult families. The user's “Neutral” first evolution is named **Normal** in the mod. It preserves the original blocky 7×6×6 head box and pixel face, rather than changing skull vertices to copy the viewer's rounded head.

## Shape changes

The independently operated viewer shows rising/curling Neutral head features. The user's later red-line edit sets the intended blocky directions and lengths more specifically: Swim starts farther back, rises rearward and finishes with a shorter upright/slightly forward tip; Power rises forward first and then curls back upward through its shorter upper piece. Power+Swim retains a broad added base across most of the head roof, a narrower middle and a small upper point: a three-step Minecraft interpretation of a cone. These are user-guided blocky additions above the fixed head, not replacements for it or claims of exact viewer geometry.

Hero/Normal retains two main sections per tip: a generally base-colored lower root and a shape/color-changing upper section. Run extends narrower points, Power uses broader caps, Fly uses thin white stalks with distinct compact lavender caps, and Swim forms broader rising points; compatible pairs interpolate their authored differences. Natural Hero head/body skin remains white. Limb, belly, halo and wing accent regions vary by specialization. Underlying named/monocolor/jewel coats retain their own skin and bounded-contrast details; shine remains the existing finish pass.

Each Hero wing is now a thin closed cuboid on the original wing joint rather than the same zero-thickness plane for every specialization. Span and height vary through the existing ten-target sampler, while the original wing-joint orientation and flap animation remain shared. The old canonical wing's back UV island was entirely transparent; only this family's new back faces mirror the existing visible front island, and thin edge faces follow the adjacent front texture and its alpha cutout. The source atlas is not edited; dynamic alpha remains exact apart from the two existing reserved head-feature body/tip swatches already used in `.57`. Facial UVs and alpha remain exact. This is an intentional wing-only UV/topology change to make the requested back views visible, not a new render pass or imported viewer mesh. No library or broad renderer rewrite is introduced.

A final close-up book frame revealed a separate root/cap overlap artifact: equal front/back depths produced striped pixels at the join. Each Hero upper cap now stays at least 0.08 model pixels deeper than its lower root, providing an authored 0.04-pixel separation on both faces through every positive-weight blend. The change preserves all XY silhouettes, head, pivots, UVs and wings. Its depth-only regression and fresh final client captures are recorded below.

The foundation resource identifiers and source names `neutral056` and `hero_normal057` remain in use. Their geometry/materials are intentionally refined. The original baby and approved HeroRun-first-type `.55` model assets remain separate and unchanged.

## Progression and save behavior

The existing policy is unchanged: first evolution selects the greatest earned-point total among Swim, Fly, Run and Power; the most recently actually raised tied ability wins, and Stamina is excluded. Adult alignment and first type lock at evolution. This update cannot convert a saved Hero adult into Dark or change a Run-first adult into a Normal-first adult.

Later specialization reads current level/progress differences on the opposing Run/Power and Swim/Fly axes, with the existing provisional **960 net progress** full-influence threshold. Compatible axes combine; biological maturity remains separate. Ordinary/combined drives, decreases and Creative edits use the same read-only morphology inputs. Rigid-box centers, positive sizes and rotations blend gradually; the existing twenty-tick client easing handles large edits. Lowering training recedes specialization without lowering biological age.

There are no new saved fields or data-format migrations. Existing adults retain their identity/care/genetics and derive the revised display from the same saved values. Adult alignment stays read-only in the Analyzer. Creative maturity remains inside the current life stage and does not itself trigger death, reincarnation or another evolution. Default biological timing is unchanged; as documented previously, full passive adult growth is 14.4 active hours against an ordinary twelve-hour adult lifespan, so care boosts or Creative maturity are needed to inspect that endpoint within the normal lifespan.

## Delivery and test recipe

Use matching **0.25.58** client/server JARs and external **Lionfish API 3.1**. Adult equipped projection additionally needs the existing Accessories/owo dependencies. The cumulative source overlay is for the complete 0.25.43 source, with inherited source-only coffin deletions; no save files are deleted by that overlay.

To create an exact Normal-first-type test adult, start with a genuinely untrained ordinary baby. Set Hero with `/chao ~ 100 Luck 0`, or Neutral with `/chao ~ 0 Luck 0`, before its first evolution. An operator can use `/chao mature`, wait for the cocoon, and confirm the Normal first type. Do not reset a previously trained baby's bars and assume its remembered tie history was erased. Set adult maturity under Stats, then compare current training with commands such as `/chao ~ 100 Run 10` and `/chao ~ 100 Fly 10` for a full-Hero Normal adult, or `/chao ~ 0 Swim 10` and `/chao ~ 0 Power 10` for a Neutral one. Use the adult's own displayed locked alignment number; conflicting alignment rejects the transaction. All command stat levels are 0–99. Set opposing stats to 0 when comparing pure endpoints, and wait about one second for a large-edit display blend.

For representative production toy playback, `/chao testtoy broom once`, `/chao testtoy broom loop` and `/chao testtoy broom stop` use the existing preview controls; `picture_book` accepts the same modes. These previews grant no rewards. Listening and independent multiplayer behavior are not established by the silent capture.
