**Follow-up:** real Solas V3.7b and Accessories checks are now complete. See [0.25.47 verification](REAL_MOD_CHECKS_02547.md), including the additional coplanar-glass banding fix.

This update builds on the complete 0.25.45 source, including the piano, organ, Analyzer, garden and Chaos Drive work. The actual toolchain is Java 21, Minecraft 1.21.1, NeoForge 21.1.219 and external Lionfish API 3.1. Install matching Chao Garden JARs on client and server.

## Changes and causes

- **Organ:** the rectangular cabinet collision forced the performer about 0.20 blocks too far from the manual. The new Chao contact clearance leaves the cabinet rear solid and retains the full player collision/outline. Babies and adults stand 0.1975 blocks closer, at the authored key front for every facing. Arm extension is capped at two model pixels; both hands target the actual front quarter of the keys. An obstructed front still prevents approach/preview and cancels contact. The final walking target stays outside the organ cell before a short contact handoff, preventing vanilla movement from jumping onto the cabinet. Existing reward, cooldown, reservation, cue and interruption behavior remains.
- **Guitar:** the old front vector opposed the actual string-face normals. A half-turn around the neck axis fixes the backwards body; the torso-relative guitar and hand targets sit closer and slightly higher. Independent OBJ-face tests check the outward string face, hands, head/body clearance and transitions.
- **Equipped flight:** vanilla LocalPlayer checks the chest item's elytra support before calling the existing companion launch hook. A client-only redirect admits the existing server-issued companion permit at that gate. Vanilla input edges, packets, server eligibility, finite budgets and ordinary elytra remain authoritative. No armor swap or new ability is introduced.
- **Back attachment:** the old anchor left a baby-sized gap from the keeper's torso. The revised torso-local anchor brings the Chao's chest to the player's back and raises the feet. Existing swimming/flight torso transforms and head-to-back blending remain in use.
- **Running:** imported walk seconds previously scaled directly with accumulated vanilla limb swing. A per-entity render clock now eases a bounded cadence, holds when stopped and shares phase across repeated render passes and Walk/Run/Dash transitions. Running posture steadies the torso/head while preserving foot motion, physical speed and stat thresholds.
- **Lobby:** glass was sent through an emissive entity material that Iris routes to opaque block-entity or spider-eyes programs. Background-only depth also allowed shader deferred sky replacement, while separately flushed glass batches could paint rear geometry over foreground tubes. An owned immediate scene buffer enforces the draw order even when Iris ignores explicit flushes on its shared entity buffer. Normal shader translucency now supplies foreground depth; uniform glass tint allows the floor, stair faces, guards, crown, tubes and ribbons to sort together. Authored sky/reflections render after deferred background replacement without writing depth, using the late unlit emissive program with stock fog temporarily disabled and restored before foreground rendering. Short radial floor spans improve sorting, and stair/rail/ribbon normals match their actual surfaces. Stair undersides, collision, openings, portal surfaces and travel behavior are retained.

No saved-state schema or authored-room revision changes are required; the rendering fixes apply to existing lobby geometry without rebuilding it. New gait timing is transient client state. Entity save/reload and preview state-preservation checks cover affected toy behavior.
