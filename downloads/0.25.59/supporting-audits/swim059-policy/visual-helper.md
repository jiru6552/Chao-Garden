This file describes the developer helper, not executed results. Root owns compilation, launch and visual inspection. The helper has `@EventBusSubscriber` and needs no production registration. Existing `*VisualSmoke*.class` JAR exclusions also exclude this helper and nested records.

## Launch switches

- `CHAO_SWIM059_SMOKE=true`
- `CHAO_SWIM059_OUTPUT=/workspace/.setup/swim059-client-final` (default; canonical final evidence)
- `CHAO_SWIM059_CASES=...` optional comma-separated original plan indexes; chosen cases retain names but are reindexed consecutively for phase/catalog output, matching .58 behavior. Unset for the complete study.
- Optional `CHAO_SWIM059_START`, `CHAO_SWIM059_LIMIT`, `CHAO_SWIM059_WIDTH`, `CHAO_SWIM059_HEIGHT` retain the .58 window/partial-run pattern under the new namespace.
- Forward those environment variables through the owned dev-client launch. Root adds its Gradle run/profile wiring. Actual Accessories scenes use installed Accessories/owo runtimes, never a replacement carry layer. If unavailable, those scenes emit explicit SKIP evidence.

Three UI scenes subsequently capture three normal world angles. Live cases use front, left and back cameras, at least three captures per angle, native 20 TPS time and wall-time verification.

## Evidence format and limits

Existing .58 native/render/capture proof formats retain their fields under strict `SWIM059_` tags: CASE, ARMED, CAPTURE, UI_CAPTURE, UI_NATIVE_VERIFIED, NATIVE_COMPLETE, RENDER_COMPLETE, VISUAL_COMPLETE. PAIR_PEAK is an additional intermediate-state proof marker. Every screenshot uses the actual Minecraft framebuffer and gets a SHA256 record after the native capture callback. Actual per-run catalog is `case-catalog.json` under the chosen output folder; it adds `first_type`, `run_power_axis`, `swim_fly_axis`, `fly_counter_percent`, `static_native_epoch` and `controlled_motion_training` to the .58 row schema.

Live morphology gain schedules use actual `train`; reductions and incidental motion/water-training correction use actual `AnalyzerStatRules`. The correction is explicit fixture control to keep the requested input schedule stable, not a production gameplay change. Rendering, navigation, water detection, toy clocks, grips, saved Chao state and server edit authorization are production paths. Audio events may execute but this helper does not claim human audio listening. Its water case proves the production advanced swimming pose in actual water, not autonomous swimming navigation across a course.
