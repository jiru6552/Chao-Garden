# Neutral Run-first morphology — 0.25.62

This update adds ordinary **Neutral / Run-first** adult development around the original blocky head. The later targets are balanced, Run, Power, Fly, Swim, Run+Fly, Run+Swim, Power+Fly and Power+Swim. A compatible pair has one shared target regardless of training order. Run/Power and Fly/Swim remain opposing axes; they are not simultaneous pairs.

## Opposing training and first identity

The delivered 0.25.61 implementation did not forbid a Run-first adult from moving toward later Power. Its generic Neutral Run renderer and secondary labels read both saved signed influence axes. `ChaoState.influence()` adds a negative Run or positive Power delta and clamps the result to −1..+1. Repeated opposing training can therefore move through balance to the opposite side while the first Run type stays locked. The other axis similarly crosses between Fly and Swim. This behavior was established by inspecting the actual delivered source, independently of the new shape choices.

The fresh viewer session also rendered a valid Power endpoint with the **Run first-type checkbox still selected**. It becomes magenta with tall upward central/rear features, unlike the deep-blue downward/backward-hooked Run endpoint. The update retains the full signed ranges rather than introducing a new clamp at balance. Power and its Fly/Swim combinations are included so that moving past balance has a coherent authored surface.

The new scoped profile reads current level bars: Run/Power is `(Power − Run) / 960` and Swim/Fly is `(Fly − Swim) / 960`, both clamped to −1..+1. Each bar is the existing `100 × level + progress`, bounded by the established level rules. These bars are distinct from the earned points and recency that choose first evolution. Current bars make ordinary drives, combined drives, reductions and absolute Creative edits select the same target. The older generic saved axes can disagree after direct level editing; this scoped profile makes labels and geometry follow the current bars without rewriting those older saved fields.

Selection requires a living mortal ordinary adult, normal character and variant, locked Neutral alignment strictly between −0.5 and +0.5, and locked first type Run. Babies, Hero/Dark adults, other first types and special/Chaos characters retain their existing policies. Adult first type and alignment remain locked. First evolution still selects the greatest earned points among Swim, Fly, Run and Power, with the most recently actually raised tied ability winning. Stamina, Intelligence and Luck do not compete, and an untouched zero-training record selects Normal.

## Garden testing

Use matching 0.25.62 client/server JARs with the existing Lionfish API 3.1 requirement. Start from a fresh Neutral baby, raise Run above the other first-evolution abilities and allow first evolution or use `/chao mature`. Confirm that the resulting adult's first type is Run. Editing an already evolved adult's bars does not change that locked first type.

For an adult locked at alignment 0, `/chao ~ 0 Run 10` supplies a full later Run axis when Power is zero. `/chao "Dash" 0 Power 10` can first cancel Run and then develop later Power as its current bar overtakes Run. Equal opposing bars restore balance. Add Fly or Swim for one compatible other-axis influence; later Fly and Swim cancel each other rather than forming a pair. The command sets one stat per call, so a previously high opposing bar still counts. Use the adult's actual locked alignment, wait about 1.5 seconds after large edits and compare biological maturity 0/50/100% in Analyzer → Stats.

Existing operator previews remain available through `/chao testtoy list`. `/chao testtoy picture_book once`, `/chao testtoy picture_book loop` and `/chao testtoy picture_book stop` use the production timeline; broom has the same modes.
