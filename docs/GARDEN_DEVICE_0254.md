# Garden transporter 0.25.4

The existing `chao_garden:garden_block` item/block now places one 2×2×2 machine using eight native cells. Its selection and collision use the same clipped cuboids as the visible mesh. The four facing rotations preserve the display and loading-pad direction. The inventory model stays within one normal inventory block, and the Chao Garden CD uses a sixteen-pixel dark vinyl sprite with a light-blue/yellow center.

`GardenTransporterBlock.PART` is `x + 2*z + 4*y` for offsets 0 or 1 along world axes. Part 0 is the minimum-X/Y/Z canonical provider; all eight cells resolve to its existing `GardenRegistry.Place`. Authored Neutral and Hero root coordinates remain unchanged. Hero faces south toward the lawn. No block entities or new registry IDs are introduced. Existing owner, Bell, Chao enrollment, contest and relocation identities retain the canonical root.

Old saved states without `PART` read default 8, retaining the original one-cell mesh and collision. A keeper can expand an old device with empty-hand use when the complete footprint has sturdy support, clear replaceable cells, no block entities or colliding bodies, and lies inside the allowed garden care field and bounds. Expansion never moves its canonical root. Foreign-owned or obstructed legacy devices remain intact and usable. Authored scene migrations preflight their full footprint separately before changing scenery.

Native BlockItem placement preflights all eight cells and writes the seven neighbors within the platform's native multi-place snapshot capture. Cancellation restores every cell and the single item. Only the root and legacy state have loot; native harvesting of any child routes the single drop through the root and removes the complete assembly. Removal callbacks clear canonical membership once. Deferred integrity checks clean broken assemblies after native placement has finished. Pistons cannot split or move its canonical provider. Existing single-cell non-garden ActivityBlock behavior is unchanged.

Regenerate with `python scripts/generate_transporter_assets.py` and `python scripts/generate_music_assets.py`; the shared asset pipeline already invokes both. The transporter generator writes all eight part meshes, four facing bindings, compact inventory/legacy models, root-only loot and the matching `GardenDeviceGeometry0254.java` boxes. Run `python scripts/validate_garden_device_0254.py --self-test` for finite assets, atlas bounds, rotation-to-part mapping, geometry parity, loot, legacy and vinyl checks. Native GameTests live in `GardenDeviceGameTests0254`, batch `device0254`, covering all four placements, provider canonicalization, harvesting, block-entity obstruction, canceled native multi-place and legacy ownership-preserving expansion.
